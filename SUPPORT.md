# Getting help

- **First run:** [quickstart](docs/quickstart.md) and [installation](docs/installation.md).
- **Tool parameters and results:** [MCP reference](docs/mcp-tools.md) and [generated schemas](docs/mcp-tools.schema.json).
- **Missing daemon, permissions, ROS or client approval:** [troubleshooting](docs/troubleshooting.md).
- **Clock interpretation:** [clock domains](docs/clock-domains.md) and [theory](docs/time-sync-theory.md).
- **Confirmed software defects:** use the bug report form in [Issues](https://github.com/tiansongyu/TimeSync-MCP/issues).
- **New device integrations:** include official API references, clock/event semantics and a reproducible validation plan in a feature request.
- **Security concerns:** follow [SECURITY.md](SECURITY.md) rather than posting details publicly.

Include the commit/version, OS, architecture, Python, client version, ROS/bridge version where applicable, exact sanitized tool parameters and structured status. Identify Synthetic data separately from real hardware evidence. There is no paid support or guaranteed response time.
